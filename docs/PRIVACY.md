# 隐私与数据处理说明

适用于 0.3.1（build 10）社区预览源码及 0.3.2（build 11–12）商店候选源码。build 12 更新图标，数据处理方式不变。商店候选仍在准备中，不代表已经上架。第三方修改版本可能改变行为，请以实际安装的来源和版本为准。

## 处理哪些数据

归档所需信息包括素材文件名、原始路径、类型、大小、拍摄日期、资源关联和可用的拍摄坐标／城市信息。iPhone 连接还需要设备标识，用于选择并确认同一部手机。

文件夹来源在本机读取目录、拍摄元数据和需要复制的内容。iPhone 来源通过 USB 读取分类及照片索引快照，在 Mac 本地筛选“由我拍摄”、日期和地点，再读取用户确认导入的原片。

**索引快照可能包含所选日期范围之外的元数据。** 日期过滤发生在 Mac 端，并不代表手机只传回这几天的索引。扫描不等于逐张读取整个图库的照片或视频内容。

## 内容保存到哪里

- 归档副本保存到用户选择的本机或已挂载磁盘上的新旅行目录。
- iPhone 索引快照保存在系统临时目录；商店沙盒候选使用应用容器中的临时目录。正常扫描、复核结束时由临时目录管理逻辑清理。异常终止可能留下临时文件，本项目不承诺安全擦除。
- 扫描清单和城市查询缓存在运行中的进程内使用；当前代码没有为它们建立持久化图库服务。
- 复制校验使用临时文件和 SHA-256 摘要；通过检查的完整素材才作为成功结果保留。无法确认身份的文件不自动删除。

手机和来源文件只读，不修改、移动或删除原件。设备信任／配对记录由系统及 USB 依赖处理，退出应用不等于撤销系统层面的信任。

## 哪些操作会联网

照片、视频和音频的归档内容走 USB 或本地文件系统，不通过 iCloud 导入，不上传到项目自建服务器。当前代码没有项目账号、广告或使用分析 SDK。

城市名称优先采用手机索引中的有效记录。如果有坐标但没有可用城市信息，应用会调用 Apple 的系统反向地理编码服务，将坐标交给 Apple 查询城市。请求不包含照片或视频文件内容。Apple 服务如何处理这些请求由其服务条款和隐私政策决定。

当前版本没有单独的“禁用城市联网补查”开关。若不接受坐标发送给 Apple，当前建议使用文件夹来源，并等待显式联网控制功能。查询失败或没有可用坐标时，无法确定地点的素材进入“位置未知”。

从源码构建时，构建工具可能联网获取 Python 和第三方依赖；这是构建过程，不是安装完成后的媒体上传。通过 GitHub 下载、提交 Issue 或阅读项目页面时，也适用 GitHub 自身的隐私政策。

## 反馈与公开资料

项目不会自动把原片或照片索引附加到问题报告。若你主动提交 Issue、截图或日志，内容可能公开可见。

请只提供定位问题所需的最少信息，并移除：私人媒体、精确坐标、真实行程、完整设备标识、配对文件、密钥、本机账户路径和其他个人信息。优先用合成数据复现。维护者不需要你提供整个照片索引数据库。

## 管理自己的副本

归档结果是普通文件，可由你在 Finder 中管理。删除应用不会自动删除已保存的旅行目录。应用没有云端账户或项目服务器中的媒体副本可供远程删除；Apple 查询与系统配对状态应通过对应服务和系统管理。

隐私行为变更应随版本更新本说明。相关问题可通过仓库 Issues 提交不含私人数据的描述；安全漏洞请参考 [SECURITY.md](../SECURITY.md)。
